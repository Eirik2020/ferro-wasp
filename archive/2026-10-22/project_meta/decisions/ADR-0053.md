# ADR-0053: Requirements Are YAML Data Rooted In W1-W7 And Checked By reqtool

Status: accepted; implemented in tools/reqtool except the app! parser and the analysis-level checks

Decided by the user on 2026-10-16/17.

Requirements live centrally in `project_meta/requirements/<subsystem>.yaml`,
never inside crate directories, so editing one cannot disturb a crate's
fingerprint. Governing requirements W1-W7 stay prose in
`governing-requirements.md`, gain stable IDs, and are the roots that YAML
requirements name in `derived_from`. W7 is reworded, and W4 gains
criticality, together with the first schema.

- IDs are `<AREA>-<NNN>`, such as `SAFE-001` and `INPUT-012`. They are stable,
  never reused, and not tied to crate names.
- `allocated_to` names items by crate-qualified path: a task by its
  definition (`ferrowasp_safety::safety_master`), a function or module by its
  path. `reqtool` resolves each one by parsing and reports dangling ones.
  Requirements are not found by file naming.
- Gates are declared in one file. Procedures stay Markdown, referenced as
  `path#heading`.
- Evidence is schema 3 records under
  `project_meta/testing/evidence/runs/YYYY/MM/`. Raw artifacts stay in `logs/`.
- Schemas are `serde` types with `deny_unknown_fields`, so neither agents nor
  people can invent fields. YAML is read with `serde-saphyr` (pure Rust,
  panic-free); `serde_yaml` is archived.

`reqtool` is a Rust library and thin CLI in this repository: `check` gives a
compact verdict for an item or board, `record` writes evidence, and `report`
and `graph` render views for people. Agents call `check` before editing.

Task topology comes from parsing each firmware's `ferroforge::app!`. The
declaration parser for `app!` and `#[group]` moves into
`ferroforge-contracts`, shared by FerroForge's macros and host tools, and is
released before `reqtool` uses it (W3). Each task's `from =` names its
definition, and group members are flat `pub use crate::x` re-exports, so a task
is unique by crate and name. Every link and flag handle is a declared local
resource, so the parse also yields the communication graph.

Tooling transition:

- retire `components.py`, `COMPONENTS.json`, `test_evidence.py` and
  `TEST_CATALOG.json`. Procedures stay; their metadata moves into the schema;
  trigger paths are dropped, because what is owed is computed;
- a one-off `reqtool import` re-fingerprints the schema 2 run records from
  their git revisions. The originals are kept unchanged;
- keep `check_repository_context.py` without its run-record checks, and
  `app_context.py`. Keep `check_rtic_boundaries.py` until its checks move into
  `reqtool`'s `analysis` level;
- old and new coexist until `reqtool` records and imports, then switch in one
  commit. Evidence is never recorded under both.
