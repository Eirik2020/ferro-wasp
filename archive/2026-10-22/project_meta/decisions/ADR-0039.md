# ADR-0039: Flight Boards Drive Four DShot600 Lanes As One Fault Domain

Status: accepted; cadence amended by ADR-0046

Board-neutral restatement of ADR-0023, ADR-0024 and ADR-0030, which recorded
it on the removed FCU3, and of the end of ADR-0004's deferral.

Four-lane DShot600 is the ESC protocol on every flight board. There is no
flight-app PWM ESC fallback; RC PWM stays shared infrastructure for servos and
auxiliary outputs.

One motor bank owns both lane timers, all four DMA streams, every motor pin, and
every waveform buffer, as one fault domain. A frame set is complete only when
all four lanes report completion. A transfer or direct-mode error, an
unexpected or duplicate interrupt, or a frame set still in flight after 1 ms
faults the whole bank: DMA requests stop, the timer output gates close, every
output is driven low, and the safety path requests disarm. Continuing on three
lanes is not permitted.

Where the chip allows, one timer starts the other in hardware (Foxeer: TIM1
TRGO to TIM8 ITR0). Otherwise the timers start back to back in software and the
skew is documented (Lucid H7: TIM3 and TIM5).

The DShot service is the only frame starter. It resends the authorized vector
every 2 ms using absolute release deadlines, since a relative delay adds a tick
and drops the cadence. `actuator_output` only updates the vector and its lease;
a nonzero command not renewed within 20 ms selects stop and requests disarm.

Unsafe code is limited to the chip backends' DMA endpoint declarations, each
documenting the compare-register address, transfer width, and stream mapping
it relies on. The apps deny unsafe code.

Pulse width, jitter, polarity margin, lane-to-lane phase, and stop latency
still need logic-analyzer measurement; neither bench runs nor flights
establish them.
