# ADR-0057: Hardware Meets The Core Through Message Contracts

Status: accepted, not yet implemented; amends ADR-0011 and ADR-0015, places ADR-0048

Decided by the user on 2026-10-16/17. Traits inside a task group let a device be
swapped; messages between a group and the core mean nothing is swapped.
`ferrowasp-io-contracts` holds only message types. The core depends on no
hardware trait.

**Serial RX.** `RxChunk`, as ADR-0011 defines it, becomes the message: bytes,
arrival timestamp, discontinuity marker and cause, UART-error marker, and
generation. The interrupt-to-reader mailbox becomes SPSC (ADR-0055).

**IMU.** IMU embedded-hal driver crate → FerroWasp IMU trait, one
implementation per sensor → IMU task group, generic over the trait →
`ImuSample` over a `state` link → core. The trait and group live in
`ferrowasp-imu`, and `ImuSample` in `io-contracts`. A sample is in the
sensor's own frame with a sensor id; rotating it to the body frame stays an
explicit step in the core (ADR-0025). It carries `data_ready_at`, a sequence
number, saturation flags, and a fault. The trait's conformance suite
(embedded-hal mocks, golden register dumps) also verifies external driver
crates.

**Actuator feedback** (formerly ESC telemetry) has no trait. Bidirectional
decode lives in the DShot output group, and BLHeli decode in an ESC-telemetry
group over `RxChunk`. Both send `ActuatorFeedback` (physical output index,
eRPM, observed-at, sequence, source, decode faults) to the safety-critical
feedback core. Each quantity has one declared source, chosen at boot by the
stored setting of ADR-0048 and never switched automatically; UART and DShot
telemetry are swapped by changing the setting and rebooting. eRPM goes to the
core. Temperature, voltage, and current go straight to the observer.

**Motor output (amends ADR-0015).** Actuator authority sends `MotorCommand`
(per physical output, `Stop` or `Throttle(normalized)`, with issued-at and
sequence) over SPSC to the output group, replacing `actuator_output`'s lock on
the shared `dshot_motors`. `DshotCommand` (direction, beep, EDT enable, save)
is accepted only while every output is `Stop`. The output group makes the
final freshness check: if its newest command is too old, it outputs `Stop` on
every output. This is a conformance requirement. Control-to-wire latency is a
measured path requirement.

**Protocol crates.** CRSF, SBUS, and BLHeli telemetry are each a standalone
crate following the embedded-hal and embedded-io standards, so they work
outside FerroWasp. Each sits behind a FerroWasp trait like the IMU's: an RC
protocol trait in `ferrowasp-input`, an ESC-telemetry trait in
`ferrowasp-feedback`. The existing `RcReceiver` enum is the boot-selected
dispatch. `sbus-rs` is external: pinned, `trust: external`, and verified by the
conformance suite. Each parser has `push` and `reset`. The RC group observes
discontinuities on ADR-0011's out-of-band handle and calls `reset`, discarding
any partial frame.
