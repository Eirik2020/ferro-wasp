# ADR-0038: Test Evidence Is Tied To Component IDs, Not Image Hashes

Status: superseded by ADR-0050

Decided by the user on 2026-10-12. A run record names the components it
exercised and each component's content ID, from
`project_meta/testing/COMPONENTS.json`. A pass carries forward, on any board,
while those components are unchanged; a change to one component re-owes only
the tests that name it. `python tools/components.py due` reports what is owed.

Before this, a pass held only for one whole-image hash, so a change to any
shared crate re-gated every board. For a hobby project that meant repeating
the same tests for unchanged code. One board can now prove a shared driver for
all boards that use it unchanged.

The flown image's own record is unchanged: tag `foxeer-candidate-16f6e8ed` in
the FerroForge repository plus the preserved binaries, never a rebuild.
`testing/README.md` and `testing/evidence/README.md` own the procedure.
