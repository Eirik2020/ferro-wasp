# ADR-0049: Dynamic Idle Raises The Motor Floor From The Slowest Motor's eRPM

Status: accepted, not yet implemented

Dynamic idle follows Betaflight's `flight/mixer.c` and `mixer_init.c` at commit
`41a5b43`, with one departure for stale eRPM. It needs bidirectional DShot
(ADR-0045).

The mixer gets an explicit output floor. Throttle and the axis mix are spread
between the floor and the maximum, and the axis rescaling's room below is the
throttle above the floor. The downstream idle clamp in
`validate_active_motor_outputs_with_idle` stays as the safety bound.

A PID loop compares the slowest motor's frequency with the target
`dyn_idle_min_rpm`. The frequency is taken after ADR-0047's 150 Hz smoothing.
The loop's output raises the floor of all four motors together, never one
motor alone. The increase is bounded:
- between zero and the static idle value until throttle is first raised after
  arming;
- between zero and `dyn_idle_max_increase` after that.

The I-term rises fast and falls slowly, and is bounded by the same cap. The
D-term acts on the smoothed frequency with about 20 ms of lag. With dynamic
idle on, the static idle offset is removed and throttle has a 1% minimum, so
the loop provides the floor.

Defaults are off (`dyn_idle_min_rpm` 0), P/I/D 50/50/50, and a 15% maximum
increase. They are stored configuration, a schema change (W6).

The departure from Betaflight is the user's decision. If any motor has had no
valid eRPM reply for longer than the 20 ms command lease, the increase holds
and the I-term stops integrating. If the data stays stale, the floor decays to
the static idle value. The hold time and decay rate are set at implementation
from logged reply-loss data, and recorded. Stale eRPM can therefore never wind
the floor up, which keeps ADR-0047's held eRPM out of motor authority. The RPM
filter still uses held eRPM.

Dynamic idle runs only while armed. Guarded-idle qualification (ADR-0048) keeps
its fixed idle command. `actuator_output` still validates every command (W1).

The blackbox records the floor increase, the P, I and D terms, and the
stale-hold state, for tuning.

Dynamic idle changes throttle scaling and idle behaviour (W6). It is enabled
only after the RPM filter and bidirectional DShot have target evidence. It then
needs the props-off checks, a stale-reply fault-injection test, and a flight
re-gate.
