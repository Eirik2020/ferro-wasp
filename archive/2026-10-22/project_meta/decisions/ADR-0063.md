# ADR-0063: An Independent Watchdog Backs Up The Safety Master

Status: accepted, not yet implemented; a new watchdog behaviour (W6)

Delegated by the user to Claude's recommendation on 2026-10-20.

**Why.** The safety master is the only disarm authority. If it hangs in
flight while the control loop runs, the craft flies on and neither an RC
disarm nor the RC-loss failsafe can stop it: Actuator Output's freshness
check needs the control loop to stop, and the arm-state cross-check
(ADR-0064) reads a flag a hung safety master leaves at "armed". A reset,
which stops the motors, is the only way out; losing disarm authority is worse
than a drop. No independent watchdog exists today:
`ferrowasp-stm32f4::watchdog` is a timer-driven I/O watchdog that expires
overdue SPI1 transactions, and nothing resets the board if the safety master
hangs.

**The IWDG** runs from the LSI, separate from the main clock tree, and once
started only a reset stops it. It is started by software at the end of init,
which probes the IMU and recovers flash for longer than the timeout. To check
in RM0090 and RM0433: a system reset stops a software-started IWDG, so
`reboot` and `reboot dfu` still work; software start leaves the option bytes
untouched.

**Feeding.** Only the safety master's own periodic check feeds it, on its own
timebase (the monotonic) at a fixed rate. The feed is not tied to the control
loop: a hung control loop is the safety master's to handle (a hard fault,
ADR-0062), and tying the two would make a dead IMU reboot the board in a loop
on the bench instead of reporting. The same periodic check tests the
control-loop and border-role heartbeats (ADR-0058, ADR-0061), not the
control loop's tick, which stops when the IMU does.

It covers whatever stops that check: a hung or livelocked safety master,
starvation by higher interrupts or a global critical section, a dead
monotonic, and a panic or HardFault loop, which today halts the MCU until a
power cycle.

**Timeout.** About 100 ms nominal. The LSI frequency varies widely between
parts and with temperature, so the nominal is set so that the shortest
possible timeout clears the safety master's worst legitimate gap by a wide
margin, and the longest is stated as a requirement, both from the
datasheet's LSI range.

**Debugging.** The DBGMCU freeze bit for the IWDG is set, so a debugger halt
does not reset the board during `probe-rs` sessions or SWD runs.

**After an IWDG reset** the boot reads and reports the reset cause (in
`device info`, the ledger and the blackbox header), clears the flags, and
refuses arming until the cause is acknowledged through the coordinator while
disarmed, as with `AcknowledgeConfigFallback` (ADR-0059).

**Evidence:** the feed decision is a host-tested pure function of the check's
timestamps; an MCU-level fault-injection image that stops feeding shows the
reset within the bound and the cause reported; the same injection props-off
with the motors at idle shows they stop.
