# ADR-0044: Accelerometer Level Is Calibrated On Command And Stored Per Craft

Status: accepted; calibration owner amended by ADR-0059

The user chose (2026-10-15) an accelerometer level calibration like
Betaflight's, started from FerroConfigurator's Setup tab, over storing gyro
bias as well: the gyro keeps calibrating at every boot.

`imu calibrate` on either command link, while disarmed and with no flash
maintenance running, averages 500 IMU samples of drone-frame gravity. It
refuses a craft that moves (any gravity axis wandering more than 0.05 g, or
any gyro axis more than 10 °/s), one leaning more than 10 degrees, and a
gravity magnitude more than 0.15 g from 1 g. The mean's offset from level, in
milli-g per drone axis, is saved with the configuration through the same
two-slot verified write as `config save`; `imu level` reports it. Stored
configuration version 7 carries the three offsets, each bounded to ±400 mg;
older versions load uncorrected.

The offsets are not configuration keys: they belong to one craft, not to a
tune exported to another. The control loop subtracts them from drone-frame
gravity before the attitude estimate only. The rate loop never reads the
accelerometer, so the calibration changes the estimated attitude (OSD, the
configurator's 3D view, a future self-level mode) and not what flies the
craft. The calibration runs in the flash manager at the lowest priority.
