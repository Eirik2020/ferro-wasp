# ADR-0036: Each Board's Facts Live In A Host-Tested Data Crate

Status: accepted; amends the location in ADR-0035

Decided by the user on 2026-10-13, over a `#[path]` test harness. A board's
physical facts (pins, DMA and serial routes, resource claims, profiles, default
stored configuration, USB identity) live in `firmware/<board>/board`, a data
crate with no chip HAL. It is a member of the root workspace, so
`cargo test --workspace` runs its tests on the host and in CI; the app's own
workspace excludes the directory and depends on it by path.

`src/board/` keeps only HAL glue (aliases and init) and re-exports the data
crate, so the app's `board::` paths are unchanged. Because a data crate cannot
import a HAL backend, the boundary between facts and glue is enforced by the
compiler rather than by convention.

The reason was measured: once the facts' tests could run, three had gone stale
unnoticed, two resource-claim counts and one route index. Everything else in
ADR-0035 stands: board support lives with each isolated app, and the RTIC shell
rules are unchanged.
