# ADR-0037: One Flash Manager Serves Every Board Through NorStorage

Status: accepted, pending target validation

Decided with the user on 2026-10-13. The storage task, `flash_manager_task`,
and its helpers live once in `ferrowasp-stm32-tasks`, over the `NorStorage`
trait in `ferrowasp-drivers`: read, page program, 4 KiB sector erase, busy, and
write-back pending and flush, which default to none. The SPI-NOR driver and the
H7 SD-card store implement it. Each app declares the task from the shared crate
and supplies only its store, default stored configuration, serial bindings and
routes, and its MSPv2 device-info function.

The two board copies were identical apart from a 20-line SD flush and a 3-line
busy check, and every storage fix had to be made twice. The trait sits in the
drivers crate because the orphan rule would otherwise force a wrapper around
the SPI-NOR driver.

ADR-0034's ownership, priority, queue, and disarmed-only rules carry over
unchanged. Moving the manager's logic into a host-tested state machine is
planned, not done.
