# ADR-0045: Bidirectional DShot Replies Return On Each Lane's Own Pin And Stream

Status: accepted, implemented on the Foxeer behind a props-off bench feature, pending target validation

Bidirectional DShot gives per-motor eRPM on every frame, for the RPM filter
(ADR-0047) and arming qualification (ADR-0048). The waveform is inverted (idle
high) and the command checksum is inverted. After each frame the ESC answers on
the same wire, about 30 us after the frame ends, with a 21-bit GCR reply at 5/4
of the bit rate.

Each lane receives on its own motor pin through its own DMA stream. Once every
lane has transmitted, each stream is rebuilt to read its pin and turned back
when every sample window has closed, before the next frame. No DMA stream is
added, and transmit stays timer compare DMA, not port-wide bitbang.

The Foxeer comes first (W5). Every Foxeer lane samples its pin's GPIO input
register, paced by its own timer channel's DMA request at three samples per
reply bit: 2.25 MHz at DShot600. Input capture cannot serve all four lanes.
Motor 4 is TIM1_CH3N on PB15, and TIM1 channel 3 captures from the CH3 pin,
PA10, which is the USART1 ESC-telemetry wire. Motor 1 shares TIM1, which cannot
both run freely for capture and run at the sampling period. One sampling
decoder serves all four lanes. Betaflight solves the same board with bitbang
DShot on F4. Its receive half, per GPIO port, is the reference.

STM32F405 erratum 2.2.19 (ES0182 Rev 19; 2.1.10 in older sheets) covers DMA2
data corruption when AHB and APB2 transfers run concurrently. In the receive
window DMA2 reads GPIO, which is on AHB, while SPI1, ADC1 and USART1 may use
DMA2 on APB2. The window is not ordered against the IMU transfer: IMU reads
follow the sensor's data-ready interrupt and frames follow the TIM4 control
tick, two independent 2 kHz clocks, so they overlap periodically. The erratum
does not apply. Its impacted peripherals are QUADSPI, FSMC with a FIFO, and
"DMA2 transfers to GPIO registers (in memory-to-peripheral transfer mode). The
transfers from the GPIOs register are not impacted." Transfers into internal
SRAM "can be performed several times but without data corruptions". The
receive path only reads GPIO into SRAM, and APB2 peripherals such as SPI1 are
not among the impacted ones. Betaflight takes SPI off DMA because its bitbang
writes GPIO, which this design never does.

A missing, short, or CRC-invalid reply is not a bank fault. It is dropped and
counted per motor (ADR-0047). The window is a fixed number of samples, about
71 us, so it always closes long before the next frame. A stream that never
completes it is a frame set still in flight, and faults the bank under
ADR-0039's 1 ms bound. A lane that cannot turn around or back also faults the
bank, as every transmit fault does.

The turnaround releases the HAL transfer and builds the stream again in the
other direction, so no stream-register access is added. The new unsafe code is
the input register's DMA endpoint and its route declarations, inside the chip
backend's documented boundary, and the user reviews it. Reply decoding is
HAL-free and host-tested in `ferrowasp-waveform`: GCR, the inverted CRC, the
eRPM period, and extended telemetry frames. It runs in the DShot service
before the next frame, never in the DMA interrupts.

The TBS Lucid H7's lanes are ordinary TIM3 and TIM5 channels. They may capture
on the same stream instead of sampling; that is decided when the Lucid is
brought level.

The inverted waveform is a DShot timing change (W6). It needs logic-analyzer
captures of both directions, the props-off DShot checks, and a flight re-gate.
