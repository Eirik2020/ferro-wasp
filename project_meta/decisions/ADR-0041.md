# ADR-0041: Motor Bench Actuation Is Capped And Explicitly Gated

Status: accepted; motor-test routing amended by ADR-0056

Board-neutral restatement of ADR-0026 and ADR-0032, which recorded the bench
images on FCU3 and Foxeer, plus FerroConfigurator's motor test.

Bench motor images need the explicit props-off gate `bench_actuator_validation`
together with `bench_equal_motors` and at most one `bench_logical_motorN_only`;
any other combination is a compile error, and physical selected-motor features
are rejected on DShot boards. A bench image caps throttle at 250 commands,
keeps RC qualification, the arming guards, the recovery latch, the bounded
fresh-command path, and sole actuator ownership, and cannot select PID or mixer
output or set a board's verification flags. A logical selection is remapped
before the command queue, so it exercises the board's logical-to-physical map.
Arming idles all four motors, so every bench image is props-off only.

Fault-injection images, such as one that reports zero eRPM for output 1 at
the qualification input, announce themselves at startup and are props-off
only.

FerroConfigurator's motor test is a runtime request the safety master accepts
only while disarmed, not arming, with the arm switch low and output enabled.
An accepted request idles one logical motor for a 250 ms lease the host renews
while its button is held; arming is refused for 2 s after the last request.
It runs over USB only.
