# ADR-0056: The Observer Is The Only Way Out And The Coordinator The Only Way In

Status: accepted, not yet implemented; amends ADR-0041, ADR-0042, ADR-0043; observer class and border priority amended by ADR-0061

Decided by the user on 2026-10-16/17.

**Out.** The observer receives from safety-critical tasks over SPSC links and
publishes a uORB-like, read-only ledger. Non-critical tasks (OSD, telemetry,
CLI, blackbox) read the ledger as a shared resource. Topics are latest-value
or queued streams; the blackbox reads a stream because it needs every sample.
The producers' never-block rule is the safety-critical part, so the observer
itself is non-critical. The ledger replaces `snapshots.rs`.

**In.** The coordinator is the safety-critical task that receives requests;
the owners it works with are its participants. One typed `Request` enum is the
whole inbound surface. Each requester (USB link, UART command line, OSD menu)
has its own SPSC queue into it. The coordinator validates content, arbitrates
between requesters, bounds its work per run, and runs one transaction at a
time:

1. ask the safety master for an arm inhibit, granted only while disarmed and
   not arming; an inhibit never disarms;
2. send the change to each participant, which stages it and acks;
3. commit, or abort if any stage failed;
4. release the inhibit;
5. publish the result, with the request id, through the observer.

Participants still check "disarmed" when they apply. The coordinator never
judges flight state; it asks the owner of that state.

An inhibit carries a lease:
- **config transaction:** a lapse without release latches an arming refusal
  until reboot, since a partial change may exist;
- **bench session:** a lapse is the normal end of a motor test. The motors
  stop and arming is allowed again.

These rules may be loosened later if the benefits outweigh the risks.

**The motor test (amends ADR-0041)** reaches the safety master only through the
coordinator. The link task is the requester, the coordinator allows one bench
session at a time, and the safety master owns the lease. Today `usb_fs` feeds
`SafetyEvent::BenchMotor` straight into the safety master's event input.

**Requests (amends ADR-0042)** such as config changes, calibration, and the
motor test travel as `Request`s, not as direct writes. Saving the
configuration does not use the coordinator (ADR-0059). Open: ADR-0042's arming
refusal while a USB host is connected reads flags written by non-critical
tasks. It must move to an inhibit lease each link holds through the
coordinator, or to a safety-critical VBUS sense. This is decided during the
redesign.

**Reboot (amends ADR-0043).** `Request::Reboot` goes through the coordinator.
The safety master resets under an arm inhibit, and refuses while armed or
arming. Today the flash manager checks `SAFETY_ARMED` itself and resets.
Quiescing storage stays non-critical: the requester asks the flash manager
first, and boot validation (ADR-0059) covers a cut write.
