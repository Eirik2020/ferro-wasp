# ADR-0059: Stored Configuration Passes One Safety-Critical Gate

Status: accepted, not yet implemented; amends ADR-0044's calibration owner

Decided by the user on 2026-10-17. Storage is untrusted input; validation is
the trust boundary.

`ferrowasp-config` is a safety-critical, HAL-free crate. It holds the schema,
value specs, `validate(config, board)`, page encode and decode, schema
migration, and the motor-map type. The flash manager and `ferrowasp-protocol`
depend on it, never the reverse.

One `validate()` runs both at boot and in the coordinator, so a change the
coordinator accepts can never be rejected at the next boot. It checks each
value against its spec and also the rules across fields and against the board:
- the motor map is a permutation;
- the loop rate follows ADR-0058;
- the actuator-feedback source is valid for the board;
- RC is bound, and no UART is bound twice;
- the RC protocol is supported on its port.

**At boot,** init decodes the page, validates it, and selects a slot. A
safety-critical config owner holds the active image and the pending image.
- An erased flash gives the board default and may arm, as on a fresh board.
- A damaged newest slot, or a `validate()` failure, falls back to the older
  slot or the default, never a clamped value. Arming is then refused until the
  pilot sends `AcknowledgeConfigFallback` through the coordinator; the safety
  master owns the refusal. It recurs on each boot until a good save overwrites
  the damaged slot.
- A schema migration arms, and is reported.

**At runtime,** live keys such as tuning change through a coordinator
transaction (ADR-0056). Boot-only keys (RC protocol, serial bindings,
actuator-feedback source, loop rate) are stored as pending, and the ledger
shows them separately from the active values.

**Saving does not use the coordinator.** The config owner publishes the
next-boot image as one ledger topic. The command line asks the flash manager,
which saves that image with the existing two-slot write and readback, and
refuses while armed. A requester can only ask for a save, never supply bytes,
and boot validation catches anything the save path corrupts.

**Accelerometer level (amends ADR-0044).** The attitude estimator is
safety-critical (ADR-0054). Calibration therefore moves from the flash
manager into the safety-critical core as a coordinator transaction:
1. take the arm inhibit;
2. the estimator's owner applies ADR-0044's stillness, lean and magnitude
   checks to its own samples;
3. stage the offsets, commit, and release.

ADR-0044's limits, its ±400 mg bound, and its rule that offsets are per craft
rather than configuration keys all stand.
